### Tempo v4 API contract — the `updatedFrom` exclusivity rule, and deletions are INVISIBLE (verified in production use 2026-07-01 … 2026-07-27)
Base **`https://api.eu.tempo.io/4`** for the EU tenant (Data Egret); auth `Authorization: Bearer <token>` (keychain service `tempo-dataegret-api`). Worklogs per account: **`GET /4/worklogs/account/{accountKey}`**; accounts: `GET /4/accounts`. Paging is offset/`limit` (**max 1000**) with the next URL handed back in **`metadata.next`** — follow it, never construct it. **★ `updatedFrom` MUST be used ALONE — it cannot be combined with `from`/`to`/`project` on the same call** (established 2026-07-01); so an incremental pull is `?updatedFrom=<YYYY-MM-DD>&limit=1000` + paging only, while a first-run full pull is `?from=2000-01-01&to=<today>&limit=1000`. **`updatedFrom` is DATE-granular**, so a client needing a precise watermark must additionally filter client-side on the full-precision `updatedAt` — correctness cannot rest on the server's granularity. An unknown or inaccessible account key returns **404** (treat as skip, not failure). Pacing: keep ≥1s between calls; on **429** Tempo documents no `Retry-After` and officially recommends a multi-minute cooldown, though a short exponential backoff suffices for small incremental windows. **★ DELETED worklogs are undetectable via `updatedFrom`** — a deleted worklog simply stops appearing, with no tombstone (established 2026-07-27 while reconciling a delta sync). Any "has anything been removed at source?" question therefore requires a **full per-account re-pull diffed against the target**, and an incremental sync must state this as a known blind spot rather than imply completeness. Separately: **`category.type` and `monthlyBudget` are both unreliable** as billable-vs-non-billable / included-hours signals (verified 2026-06-22) — do not model business rules on them.

### Jira Cloud issue enumeration + auth — the removed `/search` endpoint and token expiry (verified Jun 2026)
**The old `GET|POST /rest/api/{2,3}/search` is REMOVED** (410 since late 2025) — code written against it fails outright. Use **`GET|POST /rest/api/3/search/jql`**, whose contract differs in ways that break naive ports: pagination is **`nextPageToken`** (there is **no `total` and no `startAt`**, so no "page N of M" progress and no offset seeking), and **`fields` must be explicit** or the response carries IDs only. `expand=changelog,renderedFields` as needed; `jql=project=KEY ORDER BY created ASC` for stable enumeration. Approximate size via `POST /rest/api/3/search/approximate-count` — approximate, never a reconciliation figure. Changelog: <https://developer.atlassian.com/changelog/#CHANGE-2046>. **Auth:** basic `email:api_token` remains current, but **API tokens now expire (max 1 year)** and legacy non-expiring ones were force-expired Mar–May 2026 — mint fresh and record the expiry next to the credential's location. **Rate limits:** the points-based quotas introduced Mar 2026 apply to Forge/Connect/OAuth apps; plain API-token traffic keeps burst limits (~100 RPS GET, 50 RPS PUT/DELETE, per-issue writes 20/2s). Honor `429` + `Retry-After`. <https://developer.atlassian.com/cloud/jira/platform/rate-limiting/> Enumerate `GET /rest/api/3/field` to resolve `customfield_*` ids (the request type also surfaces as a "Customer Request Type" custom field). Export during a change freeze where possible — cursor paging can skip or duplicate rows under concurrent edits.

### JSM `servicedeskapi` — what only it exposes, the experimental-header trap, and what has NO export path (verified Jun 2026)
`/rest/servicedeskapi/` uses a **different pagination shape** from the platform API: `start`/`limit` + `isLastPage`. Endpoints: `/servicedesk`, `/servicedesk/{id}/requesttype`, **`/servicedesk/{id}/customer`** (⚠ **experimental — requires header `X-ExperimentalApi: opt-in`**, and it is the endpoint that returns customer emails), `/organization` + `/organization/{orgId}/user`, `/request/{key}?expand=sla,requestType,participant,status`, `/request/{key}/sla` (per-metric cycles with breached flag and elapsed/remaining ms), `/request/{key}/approval`, `/request/{key}/feedback` (CSAT). **Only this API exposes** request types and portal field layouts, SLA cycle *values*, approvals, organizations, portal-only customers, queues and CSAT — the platform API cannot see them. **★ SLA *configurations* (goals, calendars) have NO export API** — they must be recreated by hand in any target system; only achieved cycle values are readable. **Rich text is ADF JSON** in v3: for HTML use `GET /rest/api/3/issue/{key}?expand=renderedFields`, comments via `/rest/api/3/issue/{key}/comment?expand=renderedBody`; comment visibility is the **read-only `jsdPublic`** flag (internal comments are set through the property `sd.public.comment {"internal": true}`). Store raw ISO-8601 timestamps rather than `renderedFields` times. **Attachments:** `fields=attachment` gives metadata + a content URL; `GET /rest/api/3/attachment/content/{id}` answers a **303 redirect**, so `curl -L --user email:token` is required. **Bulk paths are not migration sources:** the issue-navigator CSV caps at **10,000 rows** (since Mar 2025) and the Backup Manager ZIP (48h between runs) **excludes Assets** and app data. Portal-only customers export at admin.atlassian.com ▸ User management ▸ JSM ▸ Export customers. GDPR: user emails are hidden unless profile visibility allows, but the JSM endpoints above do return customer emails.
