### cal_agent grid: three reusable layout/painting lessons from the slot-background fixes (2026-06-10)

- **Slot-independent ordering for vertical consistency.** When a block spans rows/slots, any per-cell ordering MUST key off stable *entity identity*, not the element's role in that cell. The bug: `BackgroundPlan` walked Starts-then-Continuations, so a meeting's color column jumped between its start slot and continuation slots. Fix: gather all items, `sort.SliceStable` by `(Event.Start, CalendarName, Summary, Color)`, then derive the mine pick + distinct others from that order. Test the invariant directly: build the SAME events as starts in slot 0 and continuations (input order shuffled) in slots 1-2, assert `eqPlan` across all three.
- **Removing a rendered element ≠ removing its data.** Dropped the continuation tick strip (obsolete once the bg wash shows ongoing meetings) but KEPT `Cell.Continuations` because the bg painter still reads it. Touch points for "stop rendering X but keep the model": the line-count method (`Cell.Lines()` no longer counts it → a continuation-only slot is height-1 clamped, a bg-washed empty cell), the renderer (drop the strip builder + its `cellLines` call), the now-dead pure helpers (`TickGlyph`, `ContinuationStrip`), and EVERY doc comment describing the old geometry. `grep -rn` the symbol across `--include='*.go'` to confirm zero dangling refs before declaring done.
- **Integer-division remainder = unpainted right-edge gap.** `colWidth := avail/7` silently drops `avail%7` columns; with a single uniform width the 7 columns + gutter + seps fall short of `gridWidth`, and `fillPane` pads the gap UNPAINTED. Fix: compute `[7]int` per-column widths distributing the remainder one column to the leftmost N, and thread it through every 7-column loop (headers, rule, all-day band, body). The pure `BackgroundPlan`/`cellLines` already take width per-call, so per-column widths are safe at render time. Test trap: a full composed frame line concatenates left|grid|right panels, so splitting on the column separator `│` includes panel content in the last chunk — bound the cell with `ansi.Cut(chunk, 0, colWidths[6])` before asserting its last column carries the bg SGR. Put the probe event in the RIGHTMOST (Sunday) column where the remainder bug actually manifested.

### Time-positioned TUI week grid: push ALL geometry into a pure, TUI-free package (cal_agent v2 step 2, 2026-06-09)

Built the v2 two-pane TUI: left free-slots panel + main 7-day time-positioned week grid (Bubble Tea v2). The structural win was a new `internal/grid` package that depends on `app`+`google` but NOT on bubbletea/lipgloss — every layout/color decision is a pure function, so the hard logic is table-tested with zero TTY. What the grid package owns and the test seams that mattered:
- **Window {StartHour,EndHour,RowsPerHour}** + `Place(start,end,loc) Placement{Row,Height,Visible}`. time→row uses **floor division** (`floorDiv`, NOT Go's truncating `/`) so a pre-window start (negative minutes) floors correctly. Duration→height clamps to `MinEventRows=1` (a 15-min event stays visible) and, when the min-height block would overflow the window bottom, **slides the block UP** to keep grid alignment. Events wholly outside the window return `Visible:false` and are dropped. Tests pinned: 9:30 floors to the 9:00 row, straddle-top/bottom clamp, last-hour min-height slide-up, floorDiv negative cases.
- **Overlap → lanes** via greedy first-free-lane packing within maximal overlap *clusters* (a run where each item starts before the running cluster bottom). Cap at `maxLanes`; surplus is dropped and reported as `Overflow{Row,Count}` for a "+k more" indicator at the cluster top. Every placed item in a cluster is stamped with the SAME `Lanes` (lanes actually used) so the renderer splits the column evenly. Tests: 3-overlap/maxLanes=3 → 3 distinct lanes no overflow; 4-overlap/maxLanes=2 → 2 placed + Overflow{Count:2}; non-overlapping → Lane=0/Lanes=1 (full width).
- **Color resolution** `Palette.Resolve(configColor, calendarID)`: valid hex (`#rgb`/`#rrggbb`, regex-validated) wins (lowercased); else a Google color-NAME map (lavender/peacock/tomato…); else a **stable fallback keyed by FNV-1a hash of the CalendarID** so the same calendar is the same color every render and across processes. Empty AND unrecognized both fall back (never blank an event). Pure → trivially tested for stability + hex/name/fallback branches.
- **All-day vs timed routing** happens in `LayoutWeek`: all-day events go to a separate top band, never the timed body. **dayIndex** buckets by local start date via day-granular subtraction (DST-safe). Status mark is pure: `StatusMark(Response)` → ✓/?/~/"" (none+declined → "").
- **Renderer composition gotcha**: do NOT splice styled (ANSI) substrings into a mutable cell string — lengths lie. Instead build each row as an ORDERED LIST of styled lane-segments (`place(row,leftCol,segWidth,styled)` filling inter-segment gaps with spaces), then `strings.Join`. Color the **foreground text**, not a filled background — far more legible across terminal themes in a narrow column. The 6-wide gutter renders `"08:00 "`; an all-day label must be ≤6 ("allday", not "all-day" which truncates mid-word).

### Two-pane Bubble Tea model: group per-pane state into structs, dual async load, shared week offset (cal_agent v2 step 2, 2026-06-09)

Restructuring a one-pane BT-v2 model into two focusable panes — the patterns:
- **Group each pane's state into its own struct** (`slotsState`, `gridState`) as fields on the root Model, plus a `focused focus` enum. Cleaner than a flat field soup and the agenda/to-do panes drop in as more structs later. The v1 tests that read `m.week`/`m.cursor` all became `m.slots.week`/`m.slots.cursor` — a mechanical but pervasive rename; budget for it.
- **Two injected loaders, two msg pairs, ONE shared offset.** `LoadFunc` (busy) + `GridLoadFunc` (grid, also returns the week's Monday). `←/→` fires **`tea.Batch(busyCmd, gridCmd)`** for the new offset; `r` refreshes both. Each result msg (`busyLoadedMsg`/`gridLoadedMsg` + `*ErrMsg`) is tagged with its offset and **dropped if `msg.offset != m.weekOffset`** — the v1 stale-guard, now applied per pane so a slow grid fetch for last week can't clobber the current one. Per-pane `loading`/`err` so one pane can error while the other shows data.
- **`tab` toggles focus; ↑/↓ ROUTE to the focused pane** — `moveVertical(delta)` dispatches to slot-cursor-move (left) or grid-hour-scroll (right). `scrollGrid` shifts the window preserving its height, clamped to [0,24]. `scrollGridToFirstEvent(now)` on each grid load opens the view on the earliest timed event (1h lead-in) rather than always 08:00. `space`/`y` always act on the free-slots panel regardless of focus (they're free-slots actions).
- **Testing tea.Batch**: the batched cmd returns a **`tea.BatchMsg`** (a `[]tea.Cmd`) — a test helper runs each child so both fake loaders record their offsets. `tea.KeyTab` is the tab key code. `tea.View` has a **`.Content` string field, NOT a `.String()` method** — assert rendered output on `m.View().Content`. A full `View()` render smoke test (sized via `tea.WindowSizeMsg{140,40}`, assert the ✓ mark + event title + both pane titles appear) catches renderer panics the pure grid tests can't.
- **Graceful narrow-terminal degrade**: compute `gridWidth = width - leftPanelWidth - 1`; if `< gutter + 7*minColWidth` show a "widen the terminal" hint instead of a corrupted layout; else shrink columns (`avail/7`, floored at minColWidth) and drop the overlap lane cap from 3→2 on narrow columns. Tested both branches via WindowSizeMsg width 140 vs 40.

### Splitting one loader into two consumers when filters diverge: collapse busy→events first (cal_agent v2 step 1, 2026-06-09)

cal_agent v2 split availability from display: free-slots = busy from `mine` calendars excluding my-declined; grid = all `visible` calendars tagged for render. Lessons:
- **When a downstream filter needs a field the reduced type lost, push the reduction down the call chain.** v1's `CalendarClient` exposed only `BusyIntervals` — but "exclude events I declined" needs per-event `MyResponse`, gone once events became busy spans. Fix: narrow the interface to `ListEvents` (the richer source) and do the busy reduction in `app`, not `google`. The concrete `*google.Client` already had `ListEvents`, so the compile-assert `var _ CalendarClient = (*google.Client)(nil)` still held and nothing in `google` changed.
- **Two orthogonal per-row config flags, two selectors, one shared iterator.** `mine` (availability) vs `visible` (display) are independent bools on `config.Calendar`. Wrote `mineCalendars`/`visibleCalendars` selectors + one `forEachAccountCalendars(selector, consume, warn)` that owns the per-account-factory-build and per-account/per-calendar warn-and-skip degradation — so both `LoadBusy` and `LoadGrid` inherit the graceful-skip contract for free and it's tested once per path. Skipping an account with zero selected calendars BEFORE building its client keeps a contributing-nothing account from triggering an auth prompt.
- **Exclusion rules differ by path — pin them in tests as a matrix.** Busy drops cancelled/transparent/zero-length/my-declined. Grid drops only cancelled + my-declined (on `mine` cals); transparent and all-day are KEPT (transparency is an availability concern, not a display one); colleague events (`MyResponse==None`) always shown even if some upstream marked declined, because the exclusion is gated on `cal.Mine`. The "colleague declined still shown" + "transparent kept in grid but not busy" cases are the ones that catch a wrong refactor.
- **Render rows carry resolved attributes, not config references.** `GridEvent` embeds `Account`/`CalendarID`/`Color`/`MyResponse` copied from config+event at load time, so the step-2 grid renderer colors-by-calendar and marks-status without re-joining to config. Hand the next increment a flat tagged slice, not a graph to walk.
- **Backward-compat for a new TOML bool = just add the field + a load test.** go-toml/v2 leaves an absent `mine` key as the zero value (false), exactly the desired default — no migration code, only a regression test that a pre-field file loads with `Mine=false` and existing flags survive. Seed the new flag's "smart default" (primary→true) at the WRITE path (`calendars sync` add branch), and PRESERVE the user's value on the update branch (the existing whole-struct copy already preserved it — only the add branch needed the `f.Primary` seed).

### Bubble Tea v2 TUI: testable model/update/view + injected seams (verified 2026-06-08, bubbletea/v2 v2.0.7, lipgloss/v2 v2.0.3, Go 1.25)

Built cal_agent's `internal/tui` (app shell + free-slots pane) plus the `internal/app` data-loader bridge and `internal/clipboard`. Patterns that tested cleanly with zero TTY/network/Keychain/clipboard:
- **Make the network+compute a single injected `LoadFunc`.** The model holds `load func(weekOffset int) (Week, []Warning, error)` and `clip Clipboard` as fields. Production wires the real Google-backed loader (in a `cmd_tui.go` in `main`, the only place the concrete client/Keychain/pbcopy bind); tests pass a synchronous fake loader + recording clipboard. The whole `Update` is then driven with synthetic msgs and asserted on resulting model state — no `p.Run()`, no terminal.
- **Async load = a `tea.Cmd` closure, never inline.** `loadCmd(offset)` captures `m.load` and returns `func() tea.Msg { ... return weekLoadedMsg{offset,...} | loadErrMsg{offset,...} }`. Tag every result msg with the offset it was for and **drop stale results** (`if msg.offset != m.weekOffset { return m,nil }`) so a slow week-N fetch landing after the user arrowed to week-N+1 doesn't clobber state. Test it: arrow right, feed a weekLoadedMsg for the old offset, assert still-loading.
- **Constructing `tea.KeyPressMsg` in tests:** `.String()` is driven by `Code`/`Mod`, NOT `Text`. `{Text:"up"}` does NOT yield "up". Use `{Code: tea.KeyUp}` → "up"; `{Code: tea.KeySpace}` → "space" (NOT " "); `{Code:'c', Mod: tea.ModCtrl}` → "ctrl+c"; printable letters `{Code:'q', Text:"q"}` → "q". A 10-line probe binary confirmed the exact strings — do that once per project. Corollary: in the Update switch, match `case "space"` not `case " "`.
- **`tea.Tick(d, fn)` exists in v2** for the transient-status-clear timer (copy confirmation auto-dismiss). `tea.WindowSizeMsg{Width,Height}` for responsive layout. Lip Gloss v2 API used: `lipgloss.NewStyle().Bold(true).Foreground(lipgloss.Color("12")).Faint(true).Render(s)`, `lipgloss.JoinVertical(lipgloss.Left, parts...)` — color is `lipgloss.Color(string)` returning `color.Color` (Foreground takes a `color.Color`).
- **Componentize View now even when only one pane exists.** `View()` = `JoinVertical(header, "", pane, "", status, "", helpbar)` with each `render*()` a method. The agenda/grid/to-do panes and accounts sidebar drop into the same join later without reworking the shell. Keep cursor/selection as **indices into the flat slot list** (`Week.Flat`), reset on week change (indices are week-relative). `y` with empty multi-select falls back to the cursor slot — nice default.
- **Data-loader bridge belongs in its own `internal/app`, not in google or freeslots.** It depends on a `CalendarClient` interface (subset of `*google.Client`: just `BusyIntervals`) + a `ClientFactory func(ctx,account)(CalendarClient,error)`. `LoadBusy` iterates accounts → visible calendars, and a **per-account factory error (ErrReauthorize) becomes a collected `Warning`, not a fatal** — other accounts still load. A per-calendar fetch error likewise warns-and-skips that one calendar. Test with a fake factory + fake client recording queried IDs: assert hidden calendars are never queried, both accounts' busy is gathered, and an auth-failing account yields exactly one reauthorize Warning while the other still returns data. Highest-value seam in the increment.

### google-api-go (calendar/v3 + tasks/v1) read layer — testable shape (verified 2026-06-08, google.golang.org/api v0.283.0)

Built cal_agent's `internal/google`. Patterns that paid off, all unit-tested with zero real network/Keychain:
- **Inject the *http.Client, not OAuth.** Split the constructor: `NewClient(ctx, clientPath, account, store)` (prod: load oauth client + token + token source) → `newClientWithHTTP(ctx, account, *http.Client)` (the testable core). Tests build the service over `httptest.NewServer(...).Client()` and then override `svc.calendar.BasePath = srv.URL + "/"` / `svc.tasks.BasePath` to point list calls at the fake server. No OAuth in mapping/pagination tests.
- **Pagination is free**: `call.Pages(ctx, func(page) error {...})` follows `nextPageToken` itself — accumulate into a slice in the callback. Test it with a handler that branches on `r.URL.Query().Get("pageToken")` and asserts the token sequence (`["" "PAGE2"]`).
- **Token write-back on refresh**: wrap `oauth2.ReuseTokenSource(tok, cfg.TokenSource(ctx,tok))` in a tiny `persistingSource` whose `Token()` compares access-token+expiry against last-seen and calls `store.Set` only when it changed. Swallow the Set error (don't fail a valid request over a Keychain hiccup). Tested by seeding an expired token + a fake token endpoint and asserting the store now holds the fresh token; a "no write when still valid" test via a Set-counting store wrapper guards against Keychain churn.
- **Keep google-api types below the package boundary** — map to plain structs (`Event`, `BusyInterval`, `Task`) in separate `*_test`-friendly mapping funcs. Highest-value table tests: all-day `date` vs timed `dateTime` (+ `time.ParseInLocation` for date-only TZ), busy extraction excluding cancelled/transparent/zero-length, Tasks due date-only-midnight-UTC quirk (`time.Parse(RFC3339, "...T00:00:00.000Z")`).
- **410 Gone**: `errors.As(err, &*googleapi.Error)` then `.Code == 410`; wrap with a "sync token expired, full resync" message so the future incremental-sync layer has a clear signal. `googleapi.Error` survives `errors.As` through the wrap.
- **Live verification surface**: a `debug` scaffolding subcommand (`calendars`/`events`/`tasks`, shared `--email`/`--days`, runs all connected accounts when `--email` omitted) lets the user confirm live reads before any TUI exists. Never print tokens.

### OAuth2 installed-app loopback flow in Go — testable shape (verified 2026-06-08, golang.org/x/oauth2 v0.36.0)

Built cal_agent's `internal/auth`. Pattern that tested cleanly with zero network/browser/Keychain in unit tests:
- **Bind ephemeral port**: `net.Listen("tcp","127.0.0.1:0")`, derive `redirectURL = http://<addr>/callback`. Clone the `*oauth2.Config` per flow and set `RedirectURL` on the copy — never mutate the caller's config (it's shared/cached).
- **Auth URL**: `cfg.AuthCodeURL(state, oauth2.AccessTypeOffline, oauth2.ApprovalForce, oauth2.S256ChallengeOption(verifier))`. `verifier := oauth2.GenerateVerifier()`; `oauth2.AccessTypeOffline` → `access_type=offline` (refresh token), `oauth2.ApprovalForce` → `prompt=consent`. Exchange with `oauth2.VerifierOption(verifier)` for PKCE. These helpers exist in v0.36.0 — don't hand-roll PKCE.
- **Testability split that paid off**: make the callback handler its own type (`wantState`, `resultCh chan`) with `ServeHTTP` — unit-test it via `httptest.NewRecorder` for state-mismatch/error-param/code-captured WITHOUT spinning a server. Make `OpenBrowser func(string) error` and `LookupEmail func(...) (string,error)` injectable struct fields; full-flow test injects a fake browser that GETs the loopback callback in a goroutine and a fake token endpoint via `httptest.NewServer` (assert `code_verifier`/`code_challenge=S256` present there). No real `open`, network, or Keychain in any test.
- **Account email within read-only scopes**: with only `calendar.readonly`+`tasks.readonly` (no `openid email`), get the account email from `GET .../calendar/v3/calendars/primary` — its `id` IS the email. Avoids adding the calendar/v3 SDK dep to `auth`; a 30-line `net/http` call suffices.
- **macOS browser open** = `exec.Command("open", url).Start()` (don't Wait). Gate on `runtime.GOOS=="darwin"` and print the URL otherwise (v1 macOS-only boundary).

### go-keyring TokenStore: interface + memory fake, never touch real Keychain in tests (verified 2026-06-08, zalando/go-keyring v0.2.8)

`keyring.Get/Set/Delete(service, account)` store a string; JSON-encode the `*oauth2.Token` into it, service="cal_agent", account=email. ### Day-granular window config beats raw durations for human editing (cal_agent, 2026-06-08)

Switched `window.back='720h0m0s'` → `back_days = 30`. Store as `int` days in TOML; expose `Back()/Forward() time.Duration` (×24h) and a `Resolve(now) (start,end)` method so in-memory math stays duration-based. If an env/flag override is still a duration string, quantize it to whole days at Merge time (round to nearest; positive sub-day rounds up to 1 so an explicit override never silently becomes 0). Far more readable in the file than `2160h0m0s`.

### go-toml/v2: nil-slice round-trip breaks reflect.DeepEqual; use omitempty (verified 2026-06-08, v2.3.1)

A `nil` slice field marshals to `key = []` and unmarshals back to a **non-nil empty slice**, so a `Defaults()`→Save→Load round-trip fails `reflect.DeepEqual` (prints identically, compares unequal). Fix is production-side, not a test hack: tag empty-by-default collection fields `toml:"name,omitempty"` so they are omitted from the file entirely — round-trips `nil`→absent→`nil` cleanly AND yields a cleaner human-editable config (no `accounts = []` noise). Alternative if you must keep the key: compare with `cmp.Diff(..., cmpopts.EquateEmpty())`. Prefer omitempty for config files.

### TOML duration pattern: wrap time.Duration with Marshal/UnmarshalText (verified 2026-06-08)

For human-editable duration config, define `type Duration time.Duration` with `MarshalText`/`UnmarshalText` (parse via `time.ParseDuration`). Renders as `'5m0s'`/`'720h0m0s'` in TOML, program holds a real `time.Duration` via a `.D()` accessor. `UnmarshalText` returning an error on a bad string gives free malformed-value rejection at Load time.

### Precedence chain implementation pattern (flags > env > file > defaults)

Clean, testable shape used in cal_agent: an `Overrides` struct of **pointer** fields (`*time.Duration`) where nil = "not set at this layer" (distinguishes absent flag from zero value); `FromEnv(getenv func(string) string)` returns Overrides (inject getenv for hermetic tests — no real env mutation); `Merge(Config, Overrides) Config` applies only non-nil fields; `Resolve(paths, env, flags)` layers LoadOrInit → Merge(env) → Merge(flags). Overrides stay in-memory — they do NOT persist to the file (test asserts on-disk file still holds defaults after a Resolve with overrides).

### First-run config: LoadOrInit sentinel pattern

`Load` returns `fs.ErrNotExist` unwrapped (via `errors.Is`) for a missing file so the caller distinguishes first-run from a parse error. `LoadOrInit(paths)` = Load; on ErrNotExist → EnsureDirs + Save(Defaults) + return defaults; second call reads the existing file untouched (test both branches). Save is atomic (temp file in same dir + rename), 0o600; dirs 0o700.

### Bounded slot-cell model beats grow-to-fit for a TUI time grid (cal_agent v2, 2026-06-09, 2nd pass)
