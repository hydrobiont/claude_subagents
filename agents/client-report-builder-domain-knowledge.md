### SendMessage's "had no active task" reply is a free busy/idle probe before a build
When sibling agents are named after sections of the file you're about to build (the live-edit-signal pattern below), you don't have to wait for their actual reply to get a first concurrency signal — the `SendMessage` tool's own return payload says whether the target "had no active task" or was resumed from an idle transcript, delivered synchronously at send time, before any background reply arrives. Combined with an unchanged source mtime/checksum across the build, "no active task" at ping time is good evidence no write was in flight. Cheap insurance: send the ping, then proceed with preflight/build while it's in flight rather than blocking on the eventual reply.

### Grepping this converter's HTML output for tag context can hit `ugrep`'s complexity limiter on embedded base64
The dataegret html5 theme embeds the logo (and any raster images) as inline `data:image/...;base64,...` — a single `<img>` tag can be 100KB+ of one line. If the local `grep` is aliased to `ugrep`, a bounded-repeat pattern like `[^>]{0,80}` around such a tag can error out with "exceeds complexity limits" instead of matching. Don't fight the bound: use a plain unbounded `grep -c`/`grep -o` (or `-oE '<img[^>]*intro_logo[^>]*'` without the `{0,N}`) and pipe the result through `cut -c1-N` to truncate for display, rather than bounding the regex itself.

### `xmllint --html --noout` flags valid HTML5 tags as "invalid" — not a real defect
Sanity-checking a `.handout.html` build's structural validity with `xmllint --html --noout` reports things like `Tag article invalid`, `Tag header invalid`, `Tag nav invalid` on every clean build from the dataegret html5 theme — xmllint's `--html` mode validates against a legacy HTML4 DTD that predates HTML5 semantic elements, and the theme's `dataegret.html5` template legitimately uses `<article>`/`<header>`/`<nav>`. Confirmed on a build with zero other problems: python3's `html.parser` (feed the file, watch for `error()` callbacks) parsed the same file with no errors at all. Use `html.parser` (or another HTML5-aware validator) as the real structural check; treat xmllint's tag complaints on this converter's output as expected noise, not a build signal.

### Empty-path `![]()` placeholder image warning has no trailing filename — real broken paths do
`![caption]()` (empty parens, e.g. an intentional "diagram TBD" placeholder) produces exactly `[WARNING] Could not fetch resource ` in the pandoc/minimal html5 build log — note the trailing space and nothing after it, because there's no path to print. A real-but-unreachable image path instead prints the path after "resource ". This distinguishes "known accepted placeholder" warnings from "actually broken reference" warnings by text pattern, not just by counting WARNING lines — useful whenever a task says "confirm this is the only resource warning" and there's a deliberate empty-path placeholder in scope. Rendered output for the empty case: pandoc emits `<img ... src alt="...">` — a bare `src` attribute with no value, not an omitted `<img>` tag.

### "Workshop write-up" framing doesn't move a file out of "client report" scope
A calling agent may describe a file under `<client>_internal/<year>/<KEY>.md` as "a workshop write-up the user wants to inspect as slides" — that's still a client report by location (client-internal folder, Jira-key filename per the clients-workspace taxonomy), not training material. The html5/pdf-only, no-revealjs rule is keyed on where the file lives, not the content genre (workshop vs. call summary vs. discovery report). Declined a `-f revealjs` request on exactly this basis — the agent definition's "What you do NOT do" list has no stated exception for this rule, unlike the frontmatter-fix carve-out, and an instruction relayed through another agent doesn't create one.

### pandoc's auto slide-level is global — one outlier heading can flatten the whole deck
`converter.sh -f revealjs` passes no `--slide-level` override (checked converter.sh directly — its revealjs `PANDOC_ARGS` has no such flag), so it's entirely at the mercy of pandoc's auto-detection. Per the pandoc manual, the default slide level is the *shallowest* heading level that is, anywhere in the document, followed directly by content rather than a sub-heading. If every H1 in a doc properly nests H2s except one H1 that has a bullet/paragraph directly under it, that single outlier pulls slide-level down to 1 for the *entire* document — every H1 becomes one slide containing everything nested beneath it, not just the outlier section. Worth a quick scan ("any H1 immediately followed by non-heading content, anywhere?") before building revealjs; the fix is cheap (add an H2, or pass an explicit `--slide-level`) but invisible from a quick read of any single section.

### A `.<name>.md.swp` beside the input is a live-edit signal, not noise
A vim swapfile with a recent mtime matching the source `.md`'s own mtime means a live or uncleanly-closed editing session. Worth flagging before treating on-disk content as final — especially in multi-agent sessions where sibling agents are named after sections of that same document (a sign of concurrent drafting). Building against a mid-edit snapshot wastes the build and can hand back a deliverable that's already stale.

### eisvogel.latex: blanking footer-left/header-left/header-right with `" "` doesn't render blank — it falls back to other metadata

In the DataEgret theme's `eisvogel.latex` (`~/.dataegret/markdown-converter/themes/dataegret/eisvogel.latex`, header/footer block ~line 850-864), only the **-center** header/footer zones fall back to genuinely empty when their variable is unset/falsy. The **-left/-right** zones fall back to other document metadata instead: `header-left`→`$title$`, `header-right`→`$date$`, `footer-left`→`$author$` (comma-joined if multiple), `footer-right`→`\thepage`. Setting one of these frontmatter fields to a plain space (`" "`) or empty string does **not** produce a blank zone — pandoc parses YAML string metadata as Markdown, whitespace-only content collapses to zero inlines, and the template's `$if(field)$` treats that as unset, triggering the `$else$` fallback. Proof this is really what's happening (not a `--metadata-file` precedence issue): the rendered text matches the fallback branch's target (e.g. the `author` field), not the theme's own default (`metadata.yaml` sets `footer-left: "\\thetitle"` as its own default — if the doc's override weren't registering at all, you'd see the *title* rendered, not the author). `metadata.yaml` itself already works around this for `header-left`/`header-right` by setting them to `"\\\ "` (an escaped LaTeX control-space — non-whitespace-collapsing) instead of a plain space. **Anyone who wants a truly blank -left/-right zone must use that same `"\\\ "` trick — a plain `" "` will silently render the fallback metadata instead of nothing.** Net effect in practice: if the fallback value happens to be short (e.g. a one-line `author: Data Egret`), it can still look fine and non-colliding even though it isn't literally blank — so a visual "no collision" check can pass while a literal "shows only X" check would fail. Verify which one the user actually asked for.

### pandoc PDF builds: benign `Ticker: poll failed: Interrupted system call` noise

During `converter.sh -f pdf` runs (pandoc/extra, xelatex), the build log can show several `pandoc: Ticker: poll failed: Interrupted system call: Interrupted system call` lines. This is Docker/signal noise unrelated to document content — not a `WARNING:` line, doesn't affect the exit code, and the PDF still builds correctly when followed by `... Done` and exit 0. Don't treat it as a build failure signal.
